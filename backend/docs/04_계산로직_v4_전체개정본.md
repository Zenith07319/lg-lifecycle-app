# 04. 계산 로직 (Calculation Logic) — v4 개정본

> 이 서비스의 모든 수치는 **현재 입력 조건 기준 추정 결과**다.
> 정확한 고장 예측이 아니며, 의사결정 참고용이다.
> "정확한 예측"이라는 표현은 절대 사용하지 않는다.

> **v3 설계 원칙 (신규)**
> 1. 진단층의 모든 측정량은 **소비전력 증가율(%)** 단일 단위로 환산한다.
> 2. 같은 단위는 가중치 없이 합산한다. 환산 불가능한 요인은 합산하지 않는다(배율 처리).
> 3. 모든 0~1 점수는 `min(측정량 ÷ 앵커, 1.0)` 형태를 따른다.
>    앵커 = "점수가 1.0이 되는 물리적 기준점"이며, **근거 증명은 앵커에만 요구된다.**
> 4. 가치판단(가중치)은 결정층에만 존재하며, 민감도 분석으로 방어한다.

## 1단계: 상태 진단 지표

### 1-0. 공통 공식

```
요인별 전력증가_i = 측정량_i 를 전력 증가율(%)로 환산
점검필요도 = min( Σ 전력증가_i / P_TOTAL_MAX , 1.0 ) × 배율(수리) × 배율(VOC)
           (최종에도 min(·, 1.0) 캡 적용)
```

- `min(·, 1.0)` 캡으로 0~1 범위가 구조적으로 보장된다 (구버전 상한 초과 버그 — 생활불편도 최대 1.43 — 해소).

### 1-1. 점검 필요도 (0~1)

> "고장 확률"이 아닌, 현재 입력 조건이 시사하는 **전력 열화 수준 기반 점검 필요도**다.

#### 1-1-1. 합산 요인 (전력 환산 가능 — 3종)

**① 증상 → 전력 증가율 추정** [E3]

사용자 입력(증상 종류 + 심각도 1~5)을 자체 실측 고장-전력 데이터의 대역으로 매핑한다.
구버전의 [증상 기본값 테이블 × 심각도 배율 테이블] 2단 곱 구조는 **폐지**한다.
(→ 무근거 상수 12개가 실측 대역 보간으로 대체. 5점 배율 1.8 TBD 항목도 자동 소멸.)

| 증상(명세서 라벨) | 전력증가 대역 (%) | 귀결 부품 | 대역 근거 |
|------|------|------|------|
| 증상없음 | 0 | — | 기준 (Faultless 1210.1W) [E3] |
| 냄새 — 곰팡이·먼지 | 2.41 ~ 5.76 | 필터 막힘 | 필터 50% ~ 커패시터+필터 [E3] |
| 전기요금증가 | 2.41 ~ 8.33 | 필터·커패시터 초기 | 필터 ~ 커패시터 노후 [E3] |
| 냄새 — 타는 냄새 | 5.76 ~ 13.41 | 커패시터 노후 | 커패시터 계열 [E3+E2] |
| 소음 | 5.76 ~ 13.41 | 커패시터 노후 | 커패시터 계열 [E3+E2] |
| 성능저하 | 9.98 ~ 24.77 | 콘덴서 막힘 | 콘덴서 30% ~ 60% [E3+E2] |
| 누수 | 24.77 ~ 36.52 | 콘덴서 중증·복합 | 콘덴서 중증 ~ 복합 [E3+E2] |
| 작동불량 | 36.52 (고정) | 복합 최대 | 실측 최대 (커패시터+콘덴서60%) [E3] |

> **[v5 변경: 냄새 라벨 2종 분리]**
> 구버전 "냄새" 단일 라벨을 "곰팡이·먼지 냄새(필터)"와 "타는 냄새(커패시터)"로 분리.
> 두 냄새는 귀결 부품·심각도·전력 대역이 달라 단일 라벨로 묶으면 과소/과대평가 발생.
> 챗봇 설문: "냄새" 선택 시 "어떤 냄새인가요?" 하위 분기 필요 (§부록D §1 참조).

```
증상_전력증가 = low + (high − low) × (심각도 − 1) / 4     # 심각도 1~5 선형 보간
```

> 증상 순위: 작동불량 > 누수 > 성능저하 > 타는냄새 = 소음 > 전기요금 > 곰팡이냄새
> 타는 냄새와 소음은 동일 대역(커패시터 계열) — 심각도로 세분화.

**② 연식 → 전력 증가율 추정** [E2]

```
연식_전력증가 = min( 사용연수 × R_AGE_YR , R_AGE_MAX )
R_AGE_YR  = 1.5 %/년     # 문헌: 에어컨 연간 효율저하 1~2%의 중앙값 [인용 확보 필요]
R_AGE_MAX = 25 %          # = 1.5 × 16.7년 (기대수명 앵커와 정합)
```

> [정합화] 코드 효율감퇴 상수 −0.025/년은 문헌 범위 상단 초과 →
> 본 개정 채택 시 **−0.015/년**으로 조정해 진단층·비용층 감퇴율을 일치시킨다.
> [한계 명시] 연식 감퇴와 증상(막힘 등)은 부분적으로 동일 물리 현상을 공유 —
> 합산에 약간의 중복 가능. min 캡과 복합 보정(1-1-3)으로 완화.
> [민감도] R_AGE_YR 1.0~2.0%/년 변동 시 등급 변경률 7.5~9.4% (부록 B) —
> 중간 민감도이므로 문헌 인용 확보가 우선 보강 대상.

**③ 관리 미이행(필터) → 전력 증가율 추정** [E3+E2]

```
필터_전력증가 = min( 미청소_월수 / 12 , 1.0 ) × 2.41%
```

- 12개월 앵커 근거 체인 [E1+E3]:
  - **LG 전자 공식 FAQ** (solutions-20150154058474, 2025.12.10):
    "극세 필터는 **2주에 한 번** 정도씩 주기적으로 청소"를 권장.
  - 앵커 해석: 12개월 = LG 권장주기(2주)의 **26배 방치** 시나리오 → 필터 50% 막힘 도달 가정.
  - 즉, "권장 준수 시 필터 영향 ≈ 0, 극단 방치(12개월) 시 최대 2.41%"의 연속 스케일.
- 2.41% = 필터 50% 막힘 자체 실측값 [E3]
- 구버전 ×0.10(10개월 포화)과 근거 체인(12개월) 불일치 → **12개월로 통일**.
- [민감도] 주기 10~14개월 변동 시 등급 변경률 0.3~1.1% — 사실상 무영향 입증(부록 B).

#### 1-1-2. 도출되는 비율 (선택값이 아닌 계산 결과)

```
P_TOTAL_MAX = 36.52 + 25.0 + 2.41 = 63.93 %
```

| 요인 | 최대 영향 | 암묵 비율 |
|------|------|------|
| 증상 | 36.52% | 0.571 |
| 연식 | 25.0% | 0.391 |
| 관리 | 2.41% | 0.038 |

> 이 비율은 설정값이 아니라 **앵커들의 비율**이다. "왜 이 비율인가"라는 질문은
> "각 요인의 최대 전력 영향이 몇 %인가"라는 사실 질문으로 환원되며,
> 답은 실측(증상·관리)과 문헌(연식)에 있다.
> 구버전의 점검 가중치 5종(0.30/0.30/0.15/0.15/0.10)은 폐기한다.

#### 1-1-3. 복합 고장 보정 (자체 실측 검증) [E3]

단순 합산의 타당성을 자체 데이터로 검증했다. 복합 실측 / 단독 합:

| 조합 | 단독 합 | 복합 실측 | 비율 |
|------|------|------|------|
| 커패시터 + 필터 | 10.74% | 5.76% | 0.54 |
| 커패시터 + 콘덴서30% | 18.31% | 13.41% | 0.73 |
| 콘덴서60% + 필터 | 27.18% | 27.86% | 1.02 |

복합 고장은 대체로 부분 가산적(평균 ≈ 0.76) → 단순 합산은 보수(과대) 방향, min 캡이 상한 통제.
**채택**: 증상·필터 동시 발생 시 보정계수 0.8 적용 (등급 변경률 9.3% — 유의미, 실측 근거 보유).

```
if 증상_전력증가 > 0 and 필터_전력증가 > 0:
    고장합 = (증상_전력증가 + 필터_전력증가) × 0.8
```

#### 1-1-4. 배율 요인 (전력 환산 불가 — 2종) [E5]

전력 단위로 환산할 근거가 없는 요인은 점수에 **더하지 않고** 위험 증폭 배율로만 쓴다.

```
배율(수리) = 1.0 + 0.1 × min(수리횟수, 3)      # 1.0 ~ 1.3
배율(VOC)  = 1.0 + 0.3 × VOC점수               # 1.0 ~ 1.3, VOC점수 = 크롤링 빈도 min-max 정규화
```

- 수리: 수리이력↔재고장 상관 데이터 부재(확인됨). "3회 포화"는 정책 선언이며
  운영 데이터 축적 후 실증 전환 계획. [민감도] 단가 ±50% 시 변경률 4.7~6.0%.
- VOC: 빈도는 위험도가 아닌 **관심도** 신호 → 증폭 상한 ±30% 제한(보조 신호 원칙).
  [민감도] 상한 ±50% 시 변경률 5.9~7.2%.

### 1-2. 생활불편도 (0~1) — 직접 입력 + 점검필요도 연동 캡

구버전 파생식(증상불편도 테이블 × 배율 + 연식×0.10)은 **폐지**한다.
점검필요도와 입력이 동일하고 계수 테이블 상관 r=0.93(Pearson 0.933/Spearman 0.929)인
중복 지표였으며, 종합위험에서 증상이 명목 13.5% 대비 실효 ~37%로 이중 계상되고 있었다.

```
생활불편도(raw) = (사용자 응답 − 1) / 4
# 챗봇 설문: "이 증상이 생활에 얼마나 불편한가요? (1~5)"
```

**불편도 캡 — 점검필요도 연동 상한** [E3 실험 검증]

```python
inconv_cap = min(0.3 + 1.5 × inspection, 1.0)
inconv     = min(raw_inconv, inconv_cap)
```

> **설계 이유**: 점검필요도가 낮은(경증·신규) 기기에서 사용자가 불편도를 높게
> 입력해도 등급이 과도하게 낮아지는 현상을 방지한다.
> 예시: 1년차 + 곰팡이냄새 + 불편도 5점 → 캡 없이 C등급(58.8점),
>       캡 적용 후 B등급(74.1점) — 실제 기기 상태와 부합하는 결과.

**실험 근거 [E3]** (`inconv_cap_experiment.py`)

| 검증 항목 | 결과 |
|------|------|
| 경증 케이스 캡 (inspection≈0.06) | cap=0.39 → 불편도 최대 약 2.6점 수준까지만 반영 |
| 중증 케이스 캡 (inspection≈0.60) | cap=1.20 → 사실상 무제한 (캡 비작동) |
| 1년차+경증+불편5 적용 전후 | C(58.8) → B(74.1), 2등급 상승 |
| 10년차+중증+불편5 | E(27.9) → E(27.9), 변화 없음 (캡 비작동) |
| 불편도 1→5 차이 보존 (경증) | 9.7점 차이 유지 → 반영감 보존 |
| 불편도 1→5 차이 보존 (중증 10년) | 25.0점 차이 유지 → 완전 반영 |

**캡 공식 해석**: inspection이 낮을수록(기기 상태 양호) 불편도 영향이 제한되고,
inspection이 높을수록(기기 상태 불량) 불편도가 점수에 완전히 반영된다.
즉 "기기가 실제로 나쁠 때만 불편 호소가 등급에 완전히 반영된다"는 직관과 일치.

### 1-3. 에너지 낭비

```
낭비 kWh = max(구형_연간_kWh − 신형_연간_kWh, 0)
낭비 비율 = 낭비 kWh / 신형_연간_kWh
```

> [중복 아님 — 기준점 차이 명시] 점검필요도와 에너지낭비는 둘 다 전력 기반이지만
> 비교 기준이 다르다. 점검필요도 = **자기 신품 상태 대비** 열화(고장 신호),
> 에너지낭비 = **최신 1등급 신형 대비** 격차(교체 편익).

> **[검토 필요: 낭비비율 재정의]** 현 정의는 신품도 비율 ~0.43에서 시작해
> (NEW_EFF_RATIO 0.70 역수 효과) 건강한 5년차가 이 항만으로 16점 감점된다.
> 시뮬레이션 결과 A등급 도달률 1.2%, 정합성 페르소나(5년·무증상·관리양호)가 77.9점 B.
> 대안: ① 등급 컷 조정(A 80→75) ② 건강등급용 낭비비율을 "신품 자기 대비 추가 낭비"
> (연식 열화분)로 재정의하고, 신형 대비 격차는 비용층(교체 편익)에서만 사용. **②안 권장** —
> "건강" 개념과 정합(신형 대비 격차는 교체 편익이지 내 기기의 건강 문제가 아님).

**에어컨 월 소비전력 추정** (효율관리제도 '표준 월간 소비전력량' 기반) [E1]

```
K_AC_월(신품 기준) = 표준_월간_kWh × (실제_사용시간 / 7.8h)
실제 K_AC_월       = K_AC_월(신품 기준) ÷ 잔존효율 η     (구형만 η<1)
```

- 기준 **7.8h/일** [E1 강화]:
  - 효율관리제도: 냉방기간 4개월(6~9월) × 941시간 → 941h ÷ 4개월 ÷ 30일 = 7.8h/일.

## 3단계: 선택지별 에어컨 관련 5년 총비용 (델타 방식)

| 선택지 | 비용 구성 |
|--------|----------|
| ① 계속 사용 | 전기비_5년(구형) |
| ② 셀프케어 | 전기비_5년(구형) + 셀프케어비 × 5 |
| ③ 수리 후 사용 | 전기비_5년(구형) + **실효 수리비** + 출장비 |
| ④ 구독 전환 | 구독료 × 60개월 + 전기비_5년(신형) |
| ⑤ 신제품 구매 | 구매가 + 전기비_5년(신형) |

단순 1차 산식 (효율 미반영):

```
② 셀프케어   = elec_old_5y × 0.976 + 셀프케어비_중간값 × 5
③ 수리후사용 = elec_old_5y × 0.75  + 실효_수리비 + 출장비
```

> **[수정: 셀프케어 0.95 → 0.976]** 자체 실측: 필터 50% 막힘 1239.2W → 정상 1210.1W,
> 절감 상한 = 29.1/1239.2 = **2.35%**. 구 5%는 실측 상한의 2배 이상인 낙관값이었음.
> 근거가 "보수적 가정"에서 **"자체 실측 상한값"[E3]**으로 격상. [무근거 → E3]
>
> **[수정: 수리후 0.60 → 0.75]** 자체 실측: 최악 복합(1652.0W) → 정상(1210.1W) 완전 수리
> 가정에도 절감 상한 = **26.7%** (콘덴서60% 단독 19.9%). 구 40%는 물리적으로 도달 불가.
> 정밀화 옵션: 증상별 차등 (경증 ×0.95 / 중증 ×0.75). [무근거 → E3]
>
> 효율감퇴 시퀀스 정합화: 계속사용 매년 **−0.015**(구 −0.025, 1-1-1 ②와 일치),
> 셀프케어 +0.024 시작(실측 2.35% 정합), 수리후 0.75 절감 반영, 신형 1.0, 하한 0.65.

### 실효 수리비 계산 — 보증기간 자동 판별 [E1]

> 연식(사용연수)은 이미 진단 입력값으로 확보되어 있으므로,
> 보증기간 내 여부를 자동으로 판별해 실효 수리비에 반영한다.
> 출처: LG전자 공식 요금/보증 안내 (lge.co.kr/support/rates-warranty-guide) [E1]

**보증기간 판별 로직**

```python
구매연도 = 현재연도 - 사용연수

# 1단계: 제품 기본 보증 (에어컨은 계절성 상품 → 2년)
제품_보증_만료 = 구매연도 + 2

# 2단계: 핵심부품 보증 (증상이 귀결 부품에 따라 적용 여부 다름)
# 커패시터, 콘덴서 → 핵심부품 아님 (기본 보증 2년만 적용)
# 컴프레서(일반)   → 핵심부품 보증 4년
# 인버터 컴프레서  → 핵심부품 보증 10년 (2015년 1월 이후 생산 모델)

if 현재연도 <= 제품_보증_만료:
    실효_수리비 = 0          # 기본 보증 내: 부품비 + 기술료 무상
                              # (출장비는 별도 청구)
elif 귀결_부품 == "컴프레서" and 구매연도 >= 2015:
    if 현재연도 <= 구매연도 + 10:
        실효_수리비 = 0      # 인버터 컴프레서 핵심부품 보증 내: 무상
    else:
        실효_수리비 = 수리비_유상
elif 귀결_부품 == "컴프레서" and 구매연도 < 2015:
    if 현재연도 <= 구매연도 + 4:
        실효_수리비 = 0      # 일반 컴프레서 핵심부품 보증 내: 무상
    else:
        실효_수리비 = 수리비_유상
else:
    # 커패시터, 콘덴서 등 비핵심부품 → 기본 보증 2년 이후 전액 유상
    실효_수리비 = 수리비_유상
```

**출장비 구조** [E1 — LG 공식 요금 안내]

```
출장비 = 28,000원          # 기본 (평일 18시 이전, 주말·공휴일 제외)
        = 33,000원          # 평일 18시 이후·주말·공휴일
        = 33,000원          # 성수기(6~8월) 기본
        = 38,000원          # 성수기 평일 18시 이후·주말·공휴일
```

> [수정] 구버전 출장비 39,600원 → **28,000원**으로 수정. [E1]
> 성수기 할증을 고려한 서비스 기준값은 33,000원 사용 권장.

**유상 수리비 범위 (증상 → 귀결 부품 기반)** [E5 — 공식 단일 공시가 없음, 범위 제시]

| 귀결 부품 | 수리 유형 | 유상 수리비 범위 | 비고 |
|------|------|------|------|
| 필터 막힘 | 셀프케어 | 0 ~ 50,000원 | 수리 불필요, 셀프케어 선택지로 처리 |
| 커패시터 교체 | 부품 교체 | 80,000 ~ 200,000원 | 핵심부품 아님, 기본 2년 후 유상 |
| 콘덴서 세척 | 청소·세척 | 80,000 ~ 150,000원 | 동일 |
| 콘덴서 교체 | 부품 교체 | 200,000 ~ 500,000원 | 동일 |
| 복합 | 복합 수리 | 200,000 ~ 500,000원 | 최악 케이스 |

```python
# 계산 시 증상별 귀결 부품으로 범위 중간값 사용
수리비_유상 = {
    "커패시터":   140,000,   # (80,000 + 200,000) / 2
    "콘덴서_세척": 115,000,   # (80,000 + 150,000) / 2
    "콘덴서_교체": 350,000,   # (200,000 + 500,000) / 2
    "복합":       350,000,
}.get(귀결_부품, 290,000)    # 귀결 부품 미확정 시 기존 중간값 폴백
```

> [한계 명시] 유상 수리비는 모델·연식·지역·수리 난이도에 따라 달라지며
> 현장 출장 진단 후 최종 견적이 확정된다. 위 범위는 의사결정 참고용 추정값이다.
> 공식 단일 공시가 없으므로 E5 정책 파라미터로 분류하며, 범위값은 서비스 운영
> 데이터 축적 후 실증 전환 계획.

비용 기준값 (비수리 항목):
- 구독: 49,000원 × 60개월
- 구매: 1,000,000 ~ 1,300,000원 (중간값 1,150,000원)
- 셀프케어: 15,000 ~ 50,000원/회 × 5회 (중간값 32,500원)
[E1/E2 — LG 서비스 공시가, **조회 일자·URL 기록 추가 필요**]

### 수리 후 사용: 재수리 기대비용 (명칭 변경)

> **[수정: "재수리 확률" → "재수리 위험 보정계수"]** 점검필요도 × 연식점수의 곱은
> 보정(calibrated)된 확률이 아니며, 문서 최상단 원칙("예측 표현 금지")과 충돌.
> 수식 유지, 명칭·설명만 변경.

```
재수리_위험_보정계수 = min(점검필요도 × 연식점수 × 부품초과보정, 1.0)
부품초과보정 = 1.0 + (부품보유기간_초과연수 × 0.15)      # 초과 시에만
재수리 기대비용 = 수리비_중간값 × 재수리_위험_보정계수
```

### D-1. 커패시터 노후

**부품 역할**: 압축기·팬 모터의 시동 토크를 보조하는 전기 부품.
**고장 메커니즘**: 커패시턴스 손실 → 모터 기동 전력 부족 → 모터 과부하 → 소비전력 증가 + 기동 불안정.

| 증상 라벨 | 발현 양상 | 근거 |
|------|------|------|
| 소음 | 웅웅·버벅거리는 소음, 기동 험 소리 | [E2] steelebrosheating.com, islandcomfort.com: "humming/buzzing sound", "stuttering sounds" — 복수 에어컨 수리 업체 일치 |

### D-2. 콘덴서 막힘 (응축기 오염)

**부품 역할**: 냉매의 열을 실외로 방출하는 실외기 열교환기.
**고장 메커니즘**: 막힘 → 방열 효율 저하 → 냉매 응축 압력 상승 → 압축기 일량 증가 → 소비전력 증가 + 냉방 능력 감소.

| 증상 라벨 | 발현 양상 | 근거 |
|------|------|------|
| 성능저하 | 찬바람 약함, 오래 돌수록 악화, 실외기 팬은 정상인데 냉방 약함 | [E2] de Oliveira et al.(2024): "incrustation in condenser → electrical current 증가 → electricity consumption 증가". icmethod.com: "냉방 성능 저하, 전력 소모 증가" |
| 전기요금증가 | 압축기 소비전력 증가 | [E3] 자체 실측: 콘덴서 30% +9.98%, 60% +24.77% |
| 누수 | 막힘 심화 → 냉매 사이클 이상 → 결빙 → 해빙 → 누수 | [E2] cjsheatingandair.com·airmechanical.com: "condenser/filter fouling → evaporator coil freezes → ice melts → water overflow" 메커니즘 체인 |
| 작동불량 | Short cycling (과열 보호 장치 발동 → 자동 차단) | [E2] 현장 기술 문서 |

| 고장 조건 | 소비전력(W) | 증가율 |
|------|------|------|
| 콘덴서 30% 막힘 | 1330.8 | +9.98% |
| 콘덴서 60% 막힘 | 1509.8 | +24.77% |
| 콘덴서60%+필터 | 1547.3 | +27.86% |

> [한계] 누수 체인은 "막힘 → 결빙 → 누수" 2단계 간접 연결.
> 각 단계는 문헌 확인, 직접 인과 단일 논문은 미확보.
