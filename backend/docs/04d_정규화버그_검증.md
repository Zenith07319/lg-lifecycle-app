# 옵션 점수화 버그 — min-max 정규화 + 무조건적 옵션 이득 (검증 기록)

> 상태: **검증 완료 · 미배포(코드 미변경)**. 팀 결정 후 적용 예정. 2026-06.
> 발견 계기: "2025년식·무증상·수리1회 건강한 새 에어컨인데 셀프케어가 1순위" 신고.

## 1. 문제
건강한 새 에어컨인데 **셀프케어/수리 후 사용이 1순위**로 나옴 (정답: 계속 사용).

## 2. 근본 원인 (2겹)
### ① min-max 정규화 증폭 — `scoring_v2.py:237-241` `_normalize`
5개 선택지의 각 지표를 **옵션끼리 min-max 정규화**(`(v-mn)/(mx-mn)`) → 제일 좋은 옵션=1.0, 나쁜 옵션=0.0. **절대 차이가 0.05여도 0~1 양 끝으로 증폭**. 건강한 기기는 모든 옵션이 비슷하게 좋은데, 계속사용을 "상대적 꼴찌"로 만들어 신뢰 0.00 처리 → 셀프케어에 밀림. (`mx==mn→0.5` 분기는 *정확히* 같을 때만 작동, 0.001 차이도 full 스트레치)

### ② 옵션의 무조건적 효율/탄소 이득 — `scoring_v2.py:196-211` `build_options`
셀프케어·수리후가 **고정 절감**(전기 ×0.95/×0.60, 탄소 ×0.95/×0.70, 낭비 ×0.97/×0.65)을 *열화가 없어도* 받음. 건강한 새 기기에 수리후 탄소 = old×0.70 = 최저 → min-max로 1.00 증폭 → 수리후 1순위.
→ **①만 고치면 ②가 드러나 오히려 수리후가 1순위**(검증됨).

## 3. 검증한 수정 (3겹)
| | 수정 | 위치 |
|---|---|---|
| ㉠ | 0~1 절대지표(점검·낭비·불편)는 정규화 제거, 절대값 사용 | `score_options` |
| ㉡ | 수리/셀프케어 절감을 **복원 가능량(점검필요도)에 비례** (`repair_eff=0.30×min(ip/0.45,1)`, `selfcare_eff=0.10×…`) → 건강하면 절감≈0 | `build_options` |
| ㉢ | 비용·탄소·초기 정규화 분모에 floor(0.20) — 작은 절대차 과증폭 차단 | `score_options` |

## 5. 남은 이슈 — P3 (경미 위생)
6년차·냄새·필터 9개월 미청소 → 수리후(85) > 신제품(80) > 셀프케어(76). 필터 청소면 될 걸 과잉치료.
- 원인①: 수리 효율(30%) > 셀프케어(10%)인데 `build_options`가 증상·필터를 안 받아 *"필터 청소로 해결 가능"* 을 모름.
- 원인②: 낭비비율 artifact(6년차도 신형 대비 격차로 교체 편익 부풀림 — v3 ②안 지목 문제)가 신제품을 띄움.
- 해결책: `build_options`에 증상·필터 전달 → 셀프케어 효율을 케이스별(필터 주도면↑)로. + 낭비비율 ②안 재정의.

## 6. 결론·주의
- 3겹 수정은 **핵심 버그를 확실히 해결**하고 노후 케이스를 망가뜨리지 않음 → **적용 가치 입증**.
- 단, 정확값(효율 0.30/0.10, floor 0.20, ip 임계 0.45)은 **정책 파라미터(가안)** — 적용 시 민감도 분석으로 방어 필요.
- 적용 절차: `score_options`·`build_options` 수정 → 6 페르소나 + 격자 재검증 → `cd app/backend && railway up` (백엔드 변경, Railway 자동배포 깨짐).
