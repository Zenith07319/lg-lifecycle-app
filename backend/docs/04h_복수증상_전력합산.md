# 04h. 복수 증상 전력증가율 합산 (Multi-Symptom Aggregation)

> 적용일: 2026-06-14 · 영향: `src/calculations_v2.py`, `app/services/calculation.py`
> 관련: [04g 이중계산분리](04g_v4보강_이중계산분리.md), [04_계산로직 v4](04_계산로직_v4_전체개정본.md)

## 1. 배경 — 무엇이 문제였나

설문은 **증상 복수 선택 + 증상별 심각도(1~5)**를 받는다(APP_SPEC). 각 증상은
MDPI 2024 실측 기반 **전력증가율 대역**(`SYMPTOM_BAND`, `ac_fault_detec.py` 산출)을 가진다.

그러나 기존 파이프라인 `_resolve_symptom()`은 복수 증상을
**`base×심각도배율`이 최대인 "대표 증상 1개"로 축약**해 엔진에 넣었다.

```python
rep = max(pairs, key=lambda p: SYMPTOM_RISK_MAP[p[0]] * SEVERITY_MULTIPLIER[p[1]])
```

→ **결과**: 사용자가 증상을 여러 개 골라도 가장 센 1개의 전력대역만 반영되고,
나머지 증상의 전력증가율은 **전량 폐기**. 증상이 많을수록 실제보다
점검필요도·에너지낭비·불편도가 낮게(건강하게) 나오는 **과소평가** 발생.

| 예시 | 기존(대표 1개) | 변경(합산) |
|---|---|---|
| 냉방약화(중간)+소음(중간) | 전력 +17.4%만 | +17.4% + 0.8×9.6% = **+25.0%** |

## 2. 변경 — 어떻게 고쳤나

선택된 **모든 증상의 전력대역을 합산**한다. 단, 무한 가산을 막기 위해
**최대 증상은 가중치 1.0, 추가 증상은 0.8(중복보정)**로 더한다.
이로써 **단일 증상이면 기존과 100% 동일**(회귀 안전), 복수면 추가 증상이 감산되어 합산된다.

### 2-1. 합산 함수 (`aggregate_symptom_power`)
```
items = [(p_i, p_i·(1-rev_i)) for 각 증상]        # p_i = symptom_power_pct(증상, 심각도)
정렬: p_i 내림차순
sym_total = Σ w_i · p_i           (w = 1.0 최대증상, 0.8 그 외)
sym_self  = Σ w_i · p_i·(1-rev_i) (셀프케어로도 안 빠지는 잔여 — rev=가역비율)
```

### 2-2. 효율 분해 (`power_excess_decomp`)
```
perm = min(1.5%/년 × 연식, 25%)                 # 영구(연식)
sym, sym_self = aggregate_symptom_power(증상목록)  # 합산
fil  = min(필터개월/12, 1) × 2.41%
rev  = (sym - sym_self) / sym                    # 전력가중 유효 가역비율(단일이면 기존 rev)
ce      = 1 / (1 + (perm+sym+fil)/100)           # 계속사용 효율
ce_self = 1 / (1 + (perm+sym_self)/100)          # 셀프케어(가역증상+필터 제거)
ce_rep  = 1 / (1 + perm/100)                     # 수리(증상·필터 전량 해소)
```
반환 키(`sc_eff/rp_eff/rev/ce/ce_self/ce_rep`)는 기존과 동일 → `scoring_v2`·`calculation.py` 무수정 호환.

### 2-3. 점검필요도·불편도
- `calculate_inspection_score`: `sym`을 합산값으로. 복합보정 0.8(증상+필터)·`P_TOTAL_MAX` 상한 유지.
- `calculate_inconvenience`: 증상별 `불편도×심각도배율`도 동일 방식(최대 1.0 + 0.8) 합산, 상한 1.0.

### 2-4. 이산 규칙
- **누수 안전 1순위 고정**: 대표가 아니어도 **선택 증상 중 하나라도 누수면 발동**(`any(k=='누수')`).
- **VOC 위험도 조회**: 대표 증상(rep) 기준 유지(전력 합산과 무관한 별도 신호).
- **report_generator/AS패스**: 새 플로우가 레거시 `symptom_type`을 안 보내 "이상없음"으로 보이던 버그를
  대표 증상 주입으로 동기화(`inputs["symptom_type"]=rep_symptom`).

## 3. 상한·과대평가 방지 (기존 정책 유지)
- 합산은 보수(과대) 방향이나, `EFF_FLOOR(0.635)` / `P_TOTAL_MAX(63.93)` / `min` 캡이 상한 통제.
- 추가 증상 0.8 가중 + 증상·필터 동시 0.8 복합보정으로 겹침 부분 감산.

## 4. 검증 (2026-06-14, 동일 입력·증상만 변경)

| 입력 | 등급 | 건강점수 | 점검필요도 | 에너지낭비 | 1순위 |
|---|---|---|---|---|---|
| 증상없음 | A | 85.6 | 20.6 | 0.130 | 계속 사용 |
| 단일(성능저하3) | C | 50.5 | 51.0 | 0.304 | 수리 후 사용 |
| 복수(성능저하3+소음3) | E | 34.6 | 64.4 | 0.380 | 수리 후 사용 |
| 4증상+누수 | E | 29.6 | 72.5 | 0.427 | 수리 후 사용 |

- **단일 증상**: 합산값 = 단독값(17.38%) → 기존과 동일(회귀 안전) 확인.
- **복수**: 증상 수 증가에 따라 점수 단조 하락, 누수 포함 시 안전 규칙 발동 확인.

## 5. 미확정 / 후속
- 추가 증상 중복보정 계수 **0.8**은 증상+필터 복합보정(MDPI 0.76)에서 차용한 잠정값.
  복수 증상 간 실측 중복 데이터 확보 시 재튜닝 대상.
